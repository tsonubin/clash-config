# Audit — 2026-10-19

Scope: product and codebase review of `clash-config` at `da3c936` (main, after PR
#1). Sections: what it is, current state, findings by area, ranked improvements,
designs for the top items. Status column reflects the branch tip of
`omp/improve-2026-10-19` where this doc lands.

## What it is and who it's for

A single-operator Vercel endpoint (`api/subscribe.ts`) that fetches a private
upstream Clash subscription and serves it rewritten as a self-contained,
China-friendly Clash config: service-scoped proxy groups (AI, Steam, Google,
YouTube, Social, Telegram, Netflix, Slack, Microsoft, Apple, Developer), a
MANUAL-first selection policy, health-checked AUTO fallback, foreign DoH routed
through the proxy, and rule providers from Loyalsoldier/blackmatrix7 via a
mainland-reachable CDN mirror.

Audience: the operator (Shay) and whoever he shares the token-gated
`sub.tsonubin.com/api/subscribe` link with. Clients in use: Clash Party, Stash,
mihomo, Clash Verge. The design target is one server with several protocols
(REALITY / Hysteria2 / SS2022 / AnyTLS), not a multi-region airport — see the
module header in `api/rewrite.ts`.

## Current state

- Small, readable codebase: `api/rewrite.ts` (~470 lines, all config
  generation), `api/subscribe.ts` (~100 lines, HTTP layer), 11 regression tests
  in `tests/rewrite.test.cjs`. Typecheck and tests pass on Node 24.
- The MANUAL-first routing policy, self-contained DNS/sniffer requirement, AI
  relay fallback chain, and Steam direct-download split are documented in the
  README and pinned by tests. Config generation is genuinely self-contained —
  no client-side override toggles required.
- Production is live and token-gated (unauthenticated request to
  `sub.tsonubin.com/api/subscribe` returns 401 as of 2026-10-19).
- npm is the package manager (`package-lock.json`); no CI, no lint config, no
  license file.
- Remote branch `shay/pin-portal-ephemeral-links-c59c` (unmerged, authored by
  another session) refactors `api/subscribe.ts` into `api/subscription.ts` and
  adds a PIN portal. Anything landing in `api/subscribe.ts` on this branch will
  textually conflict with that work.

## Findings

### Security

1. **CRITICAL — live SOCKS5 relay credentials in git history of a public
   repository.** The deleted Clash Party override scripts
   (`clash-rewrite.js`, `ai-reroute-only.js`; introduced in `b8fcf85`,
   `737a1e5`, removed in `4967db0`) hardcode the relay IP, username, and
   password as top-level constants. The GitHub repo is public
   (`raw.githubusercontent.com/tsonubin/clash-config/main/README.md` returns
   200 unauthenticated), so anyone can recover the full relay credentials from
   history today. Values are deliberately not reproduced in this document.
2. `?token=` comparison is a plain `!==` (timing-unsafe in theory; low practical
   risk at this scale) and auth silently switches **off** when `SUBSCRIBE_TOKEN`
   is unset, while README and `.env.example` present the token as required. The
   served config carries node and relay credentials in plaintext, so an
   accidentally open deployment leaks everything. Production is currently
   configured correctly (401 probe above).
3. `?url=` escape hatch (`ALLOW_URL_OVERRIDE=1`) is SSRF-shaped, as its own
   docs admit: a token holder can make the function fetch arbitrary URLs. Error
   responses echo `err.message` from fetch/parse into the HTTP body, which can
   include upstream host details or YAML content snippets. Acceptable for an
   opt-in hatch, but error text should be generic with detail kept in logs.
4. No secrets in the working tree; `.env*` gitignored except `.env.example`.
   Dependency tree is minimal (`js-yaml` only) and lockfile-committed.

### Bugs / correctness

1. **Malformed upstream entries break or corrupt the output** (reproduced):
   - a `null`/non-object entry in `proxies` throws a `TypeError` → 500
     "Rewrite error: Cannot read properties of null";
   - an entry without a `name` yields `null`/missing members in `⚡ AUTO` and in
     the emitted proxy list — a config Clash clients reject;
   - duplicate node names pass through silently (mihomo rejects duplicate
     proxy names);
   - a non-map top-level document (e.g. a bare string) throws `TypeError` and
     is reported as a 500 "Rewrite error" rather than a 502 upstream problem.
2. **`ALLOW_URL_OVERRIDE=1` does not do what it documents.** `.env.example`
   says `?url=` "override[s] SUBSCRIPTION_URL at request time"; the code is
   `configuredUrl || (allowUrlOverride ? queryUrl : undefined)`, so a configured
   `SUBSCRIPTION_URL` always wins and `?url=` only acts as a fallback when the
   env var is empty.
3. `await upstream.text()` is outside any try/catch: a mid-body network failure
   becomes an unhandled 500 instead of a 502.
4. `RELAY_PORT=""` (empty string, as opposed to unset) parses to `0` and throws
   a 500 instead of falling back to the default 443.
5. `⚡ AUTO` and `↩ AI-FALLBACK` are byte-identical groups (same members, type,
   health check). AI-FALLBACK is selectable UX, but the duplication doubles
   health-check traffic for the same nodes.

### Performance

- Every request fetches the upstream subscription with `Cache-Control:
  no-store`. Fine at personal scale; wastes upstream quota if clients refresh
  aggressively and adds a cold-fetch latency to every subscription update.
- Rule providers are fetched by clients directly from the CDN mirror (24h
  interval, 17 providers) — good: the endpoint is not a rule CDN.
- `lazy: false` on AUTO/AI fallback groups probes every node every 60s per
  group. Small, but duplicated per identical group (see bug 5).
- YAML parse + dump per request is negligible for subscription-sized inputs.

### UX

- Group defaults (MANUAL-first, Apple DIRECT, FINAL→MANUAL), quota header
  passthrough (`subscription-userinfo`), and the `store-selected` override
  caveat are documented and deliberate. Good.
- Error bodies are plain text with operator-grade detail (500/502 strings);
  fine for the audience, but they currently leak internals (see security 3).
- No landing page or usage help at the bare domain — acceptable; the remote
  portal branch addresses exactly this.

### DX

- No CI: nothing enforces typecheck/tests on push or PR. The last merge (PR #1)
  was hand-checked.
- `npm test` emits a build via `tsc --noEmit false --rootDir . --outDir
  .test-build` — a CLI override of `noEmit: true`. Works, but the test build is
  undocumented magic and recompiles the world on every run.
- Tests are behavior-focused and lean (group policy, DNS, relay, Steam
  routing); `api/subscribe.ts` has zero coverage — the HTTP contract (auth,
  status classification, override) is untested.
- No lint/format config; style is consistent by hand.

### Docs

- README is strong on policy and operations (deploy steps, troubleshooting,
  relay semantics). Gaps: no license statement; the trailing troubleshooting
  bullet ("double slash … handled correctly in the current code") is a
  historical note with no action; nothing documents the
  `.test-build` compile step or the Node version actually used.

## Designs for top items

### 1. Relay credential rotation (needs Shay)

Rotate at the relay provider first — history is public and the values are
already harvested; no code change reduces that exposure. Then choose: (a) accept
the leak and move on (simplest; the old values are dead), or (b) purge history
with `git filter-repo` and force-push — destructive, coordinated, and required
only if the old values must never be enumerable. Note the same history pins the
relay IP; if that host is a VPS, consider rotating its address or tightening
firewall to expected egress. Nothing in the current tree needs changing: the
relay is env-driven (`RELAY_*`) and `.env.example` is clean.

### 2. `rewrite()` input hardening (landed)

Single normalization pass at the top of `rewrite()`:
`Array.isArray(config.proxies)` entries must be objects with a non-empty string
`name` and a string `type`; drop violators and duplicates by name (keep first,
log count via thrown detail only when nothing survives). Non-object top-level
document → throw a dedicated "Upstream subscription is not a Clash config"
error, which the endpoint maps to **502** (not 500). Guarantee: whatever
survives is exactly the node list every group references, so no `null`/undefined
member can reach the emitted config. One regression test with a junk-laden
fixture asserts junk is dropped, duplicates collapse, and the all-junk case
throws the clean error.

### 3. Endpoint error hygiene + `?url=` precedence (landed)

- Precedence: when `ALLOW_URL_OVERRIDE=1` **and** `?url=` is present, `?url=`
  wins; otherwise `SUBSCRIPTION_URL`. Matches `.env.example`'s "override".
- Wrap `upstream.text()` in the fetch try/catch → 502 on body-read failure.
- Client bodies carry no upstream-derived text: fetch and parse failures return
  fixed strings ("Upstream subscription fetch failed", "…is not valid YAML")
  with the real `err.message` going to `console.error` (Vercel logs); rewrite
  errors keep their message, which is generated internally (never upstream
  content). No upstream URL or YAML snippet reaches a caller.
- Handler-level tests (mock `fetch`, mock req/res) own this contract: 401
  without/with wrong token, 502 classification for fetch/parse failures with
  no internal detail in the body, override precedence in both directions, and
  the happy path returning rewritten YAML plus `subscription-userinfo`
  passthrough.

### 4. Timing-safe token comparison (landed)

Hash both sides (`crypto.createHash('sha256')`) and compare with
`crypto.timingSafeEqual` on the digests — fixed-length compare, no early exit,
no length leak. Same observable behavior (401 vs 200), so no new test; the
handler tests in item 3 keep guarding the auth contract itself.

### 5. Fail-closed auth (landed, opt-in)

`REQUIRE_SUBSCRIBE_TOKEN=1` makes the handler refuse every request with 503
when `SUBSCRIBE_TOKEN` is unset, instead of silently serving the
credential-bearing config unauthenticated. The default is deliberately
unchanged: with the flag unset, a missing token still means an open endpoint,
so no existing deployment breaks at deploy time. Recommended in production;
`vercel dev` can leave it off. Flipping the default (open mode behind an
explicit opt-out) remains possible later without further code churn.

### 6. CI (landed)

Single GitHub Actions workflow, Node 20 (matches Vercel runtime), `npm ci`,
`npm run typecheck`, `npm test`, triggered on push and pull_request. No matrix,
no lint — the suite runs in seconds.

### 7. Subscription response caching (landed, default TTL)

Successful responses now carry `Cache-Control: public, s-maxage=60,
stale-while-revalidate=600`; every error path defaults to `no-store`. The
token is part of the URL, so the edge cache key includes it and an
unauthenticated caller can never hit a cached body. The default trades up to
60s of stale node set (and quota header) after a subscription change for
fewer upstream fetches and faster client refreshes — reasonable for a config
that changes rarely. Caveat retained: whether Vercel honors `s-maxage` on
function responses must be confirmed on the real deployment (if it doesn't,
the header is inert and behavior is as before).

### 8. Reject-list precedence (landed: behavior kept, comments fixed)

`RULE-SET,reject,REJECT` is deliberately emitted before the pinned service
suffixes: an ad/tracker on a proxied domain still dies. The consequence — a
domain in the reject set is rejected even when pinned in `AI_SUFFIXES`/
`SLACK_SUFFIXES` — is now stated in the code comments instead of
contradicted. If a pinned domain is ever swallowed by the reject list, the
fix is to drop it from the reject source or switch to pins-win ordering
(emit the pinned `DOMAIN-SUFFIX` rules before `RULE-SET,reject`).
